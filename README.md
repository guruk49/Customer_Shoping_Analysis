# Customer Shopping Behaviour Analysis

An end-to-end data analytics project that explores customer shopping
behaviour using **Python, SQL and Microsoft Power BI**. The project
combines data preparation, SQL-based business analysis and an
interactive dashboard to examine purchasing patterns, product ratings,
discounts, shipping preferences, subscriptions and customer segments.

## Project Overview

The project follows this workflow:

1.  **Python (Jupyter Notebook):** inspect and prepare the customer
    shopping dataset.
2.  **SQL:** answer ten business questions using aggregations, filters,
    subqueries, CTEs and window functions.
3.  **Power BI:** present customer and sales measures through KPI cards,
    charts and slicers.

## Tools and Technologies

## Python Data Preparation

The notebook includes these preparation steps:

-   Load the customer shopping CSV into a pandas DataFrame.
-   Inspect sample records, data types, descriptive statistics and
    missing values.
-   Fill missing `Review Rating` values using the median rating within
    each `Category`.
-   Standardise column names to lowercase with underscores.
-   Rename `purchase_amount_(usd)` to `purchase_amount`.
-   Create an `age_group` field using four quantile-based groups:
    `Young Adult`, `Adult`, `Middle_aged` and `Senior`.
-   Map purchase-frequency labels to day values in
    `purchase_frequency_days`.
-   Compare `discount_applied` with `promo_code_used` and remove the
    latter column in the notebook workflow.

## SQL Analysis

The SQL script contains ten business questions:

1.  What is the total revenue generated by male versus female customers?
2.  Which customers used a discount but still spent at least the average
    purchase amount?
3.  Which five products have the highest average review rating?
4.  How do average purchase amounts compare between Standard and Express
    shipping?
5.  Do subscribed customers spend more? Compare customer count, average
    spend and total revenue.
6.  Which five products have the highest percentage of purchases with a
    discount applied?
7.  How many customers belong to the New, Returning and Loyal segments?
8.  What are the top three most purchased products within each category?
9.  Among customers with more than five previous purchases, how many are
    subscribed versus not subscribed?
10. What is the revenue contribution of each age group?

### SQL concepts used

-   `SELECT`, `WHERE`, `GROUP BY`, `ORDER BY` and `LIMIT`
-   Aggregate functions: `SUM`, `AVG` and `COUNT`
-   Conditional expressions with `CASE`
-   Scalar subqueries
-   Common Table Expressions (`WITH`)
-   Window functions: `ROW_NUMBER()` and `PARTITION BY`

## How to Run the Project

### 1. Get the repository

``` bash
git clone <your-repository-url>
cd <your-repository-folder>
```

### 2. Install Python dependencies

``` bash
pip install pandas jupyter
```

### 3. Add the dataset

Place `customer_shopping_behavior.csv` in the location expected by the
notebook. If your CSV is stored elsewhere, update the notebook's file
path.

### 4. Run the notebook

``` bash
jupyter notebook
```

Open `portfoli1 project.ipynb` and run the cells in order.

### 5. Run the SQL analysis

-   Open `sql project complete.sql` in a SQL client connected to the
    database containing the customer table.
-   Ensure the table is named `customer` and includes the columns
    referenced in the queries.
-   Run the queries and review the result sets.

The supplied SQL uses PostgreSQL-style numeric casting (`::numeric`). If
you use another database system, adjust the casting syntax as required.

### 6. Open the Power BI report

Open `completed project data analysi.pbix` in Power BI Desktop. If Power
BI requests a data source or credentials, connect it to the
corresponding customer dataset and refresh the report.

## Notes and Validation

-   The project files define the analysis workflow and queries;
    numerical findings should be reported only after running them
    against the source dataset.
-   Confirm that the CSV column names and category/frequency labels
    match the values expected in the notebook.
-   Review the customer-segment logic in the SQL: the current query
    labels `previous_purchases = 1` as `New`, values from 2 to 10 as
    `Returning`, and all other values as `Loyal`.
-   Check the discount-percentage calculation for integer division in
    your SQL database. A decimal expression such as
    `100.0 * ... / COUNT(*)` avoids integer truncation in systems that
    use integer division.
-   The subscription query for repeat buyers returns counts by
    subscription status; it does not by itself calculate a subscription
    rate.
